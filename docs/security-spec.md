# Security Specification

## Threat Model & Protections
- **SQL Injection**: Prevented by architecture. No SQL is generated by the LLM. All SQL is parameterized via psycopg3.
- **Direct DB Access**: The LLM and MCP server cannot access the DB. They only call the REST API.
- **Data Exfiltration**: The DB roles (`sre_read`, `sre_ops`) are explicitly denied access to application table data (`SELECT` on app tables is blocked).
- **PID Recycling Protection**: When cancelling/terminating sessions, the API validates the `(pid, backend_start)` pair. If `backend_start` has changed, the command is rejected.
- **Audit Trail**: Every POST endpoint must generate an audit log entry (before execution intent, and after execution result).
- **Destructive Actions**: All POST endpoints require explicit parameters (e.g., `confirm: true` or `reason`) and are isolated to the `sre_ops` role. `VACUUM FULL` should not be enabled by default.
